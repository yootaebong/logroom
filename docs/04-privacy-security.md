# 04 · Privacy & Security

프라이버시는 이 제품의 **핵심 가치이자 세일즈 포인트**다. "당신의 프롬프트·업무 기록은 절대 내 서버로 가지 않는다."
소스를 MIT 로 공개하므로 "로컬 전용" 주장은 **누구나 코드로 확인할 수 있다**(ADR-0018). 여기에 **투명성·기본값**을 더해 신뢰를 증명한다.

## 원칙 (타협 불가)

1. **로컬 온리**: 모든 데이터는 사용자 기기에만 저장. 기본 상태에서 **아웃바운드 네트워크 0**.
2. **텔레메트리 0(기본)**: 사용 분석/크래시 리포트는 **opt-in**만.
3. **명시적 네트워크**: 모든 외부 호출은 문서화·설정에서 토글 가능·"네트워크 활동" 화면에 표시.
4. **최소 수집**: 필요한 것만. 사용자가 소스/프로젝트 단위로 캡처 제외·일시정지 가능.

## 네트워크 정책 — 모든 아웃바운드 호출 열거

| 호출 | 시점 | 기본값 | 대상 |
|------|------|--------|------|
| 인제스트 서버 | 상시 | on | **127.0.0.1 로컬 전용** (아웃바운드 아님) |
| SaaS 커넥터(Linear/Slack/…) | Pro, 사용자가 연결 시 | **off** | 해당 서비스 API만 |
| 라이선스 검증 | 라이선스 입력 시 | 오프라인(서명검증) | 없음(옵션: 온라인 활성화) |
| 업데이트 확인 | 시작 60초 후 + 24시간 간격 | **on(opt-out 가능)**, ADR-0013 | `releases.logroom.app`(버전 문자열만 전송) |
| 크래시/분석 | — | **off** | (opt-in 시) 수집 엔드포인트 |
| AI 요약·재개 브리핑·업무평가서 | 사용자가 생성할 때(자동 생성은 opt-in) | **off**(opt-in, ADR-0016) | 사용자가 고른 CLI/API(본인 계정). 전송 내용 = 발췌(미리보기로 확인·수정). 평가서는 평가 프로필·목표도 함께 실린다(ADR-0017) |

> **신규 설치 직후 = 완전 오프라인**이 원칙이지만, **업데이트 체크는 유일한 예외**다(ADR-0013).
> 보안 수정을 사용자에게 전달할 방법이 필요해 기본 on이지만, 전송 정보를 "현재 버전 문자열"로
> 최소화하고(사용자 식별자·텔레메트리 없음) `~/.logroom/config.json`의 `checkUpdates`로 언제든
> off(opt-out) 할 수 있다. 새 버전 발견 시에도 **자동 다운로드는 하지 않고 알림만** 하며, 다운로드·
> 설치·재시작은 매 단계 사용자가 직접 눌러야 진행된다(자동화 없음). 체크/설치는 FE가 업데이트 서버에
> 직접 fetch하지 않고 Rust 커맨드(`check_update`/`install_update`)로만 노출되어 네트워크 발생 지점이
> 코드 한 곳(`update.rs`)에 고정된다 — 그 외 이 표에 없는 아웃바운드 호출은 없다.

> **앱 ≠ 마케팅 사이트**: 랜딩(`apps/web`)의 애널리틱스/이메일 수집은 **사이트에서만**. 데스크톱 앱은 텔레메트리 0을 영구 유지 — 둘을 절대 섞지 않는다. (ADR-0011)

## 저장 & 키 관리

| 자산 | 위치 | 보호 |
|------|------|------|
| DB(`logroom.db`) | `~/Library/Application Support/LogRoom/` | perm 0600, (옵션) **SQLCipher** 암호화 |
| 인제스트 토큰 | `~/.logroom/ingest.json` + 키체인 | 0600, 로컬 전용 |
| SaaS API 토큰(Pro) | **OS 키체인만** | 평문 파일/DB 저장 절대 금지 |
| 라이선스 키 | 앱 설정 + 키체인 | Ed25519 공개키로 로컬 검증 |
| 업데이터 서명 | 앱 내장 공개키 | private key는 저장소 밖(gitignore `*.key/*.pem`) |

## 인제스트 서버 보안

- **127.0.0.1 바인딩만**(0.0.0.0 금지) → 같은 기기 밖에서 접근 불가.
- 모든 요청 `X-LogRoom-Token` 검증(상수시간 비교).
- CORS: 확장 origin만 허용(M3). 그 외 거부.
- 페이로드 크기 제한 + 레이트 리밋(로컬 폭주 방지).

## 캡처 프라이버시 제어 (사용자 통제)

- **일시정지**: 트레이에서 원클릭 캡처 중지.
- **소스/프로젝트 제외**: 특정 툴/레포는 캡처 안 함(예: 회사 레포 제외 가능).
- **시크릿 스크럽**: body/title 저장 전 정규식 마스킹(API 키/토큰/비밀번호 패턴). 기본 룰셋 + 사용자 추가(상세는 아래 절).
- **삭제권**: 이벤트/스트림/기간 단위 삭제, 전체 초기화.

## 시크릿 스크럽 (M4, `src/capture/scrub.rs`)

캡처된 이벤트를 DB에 저장하기 **직전**에 정규식으로 알려진 시크릿 패턴을 찾아 `[REDACTED:<type>]`로
마스킹한다. 적용 지점은 **파일감시(watch.rs, claude/kiro 공통) + HTTP 인제스트(`/v1/ingest`) 두
진입점 모두** — 어느 경로로 들어오든 DB에는 스크럽된 값만 저장된다. 기본 **on**(`~/.logroom/config.json`의
`capture.scrubSecrets`, 기본값 `true` — 프라이버시 기본값 원칙에 따름). `false`로 끄면 원문 그대로 저장한다.

**적용 대상**: `stream.title`, 각 `event.title`/`body`, `tool_use` essential 정책의 `metadata.inputPreview`
(문자열)만. `bodyPolicy: "full"`일 때의 `metadata.input`(원본 tool input object) 등 그 외 metadata 키는
스코프 밖(문자열 필드가 아니거나 이번 M4 대상이 아님).

**패턴 목록**(순서 중요: 구체적인 패턴을 먼저, 범용 패턴을 마지막에 적용):

| 타입 | 패턴 | 비고 |
|------|------|------|
| `anthropic` | `sk-ant-` + 20자 이상 | `openai`보다 먼저 매치(부분집합 방지) |
| `openai` | `sk-` + 20자 이상 | |
| `aws` | `AKIA` + 16자(대문자/숫자) | |
| `github` | `ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_` + 36자 이상, 또는 `github_pat_` + 22자 이상 | |
| `slack` | `xox[baprs]-` + 10자 이상 | |
| `private_key` | `-----BEGIN … PRIVATE KEY-----` ~ `-----END … PRIVATE KEY-----` | 멀티라인 PEM 블록 전체 |
| `bearer` | `Bearer ` + 20자 이상(대소문자 무관) | |
| `generic_kv` | `api_key`/`secret_key`/`access_token`/`client_secret`/`password` + `:`\|`=` + 8자 이상 값 | **키 이름·구분자는 보존**, 값만 치환(false positive 최소화 위해 값 길이 하한 적용) |

매치가 없으면 할당 없이 원문을 그대로 반환한다(불필요한 복사 방지).

**한계**:
- **기존 저장분 미소급**: 이 스크럽은 신규 캡처(ingest) 시점에만 적용된다. 현재 소급 마스킹 수단은
  없음(기존 저장분은 유지 — 추후 관리 기능 예정).
- 정규식 기반이라 알려진 패턴 밖의 시크릿(비표준 포맷, 사내 전용 토큰 등)은 걸러지지 않을 수 있다 —
  최종 방어선은 "소스/프로젝트 제외" 기능(위 캡처 프라이버시 제어)이다.

## 캡처 일시정지 의미론 (M4, `src/capture/watch.rs` + `src/ingest.rs`)

"일시정지"는 **영구 미기록**을 의미한다 — 일시정지 중 발생한 활동은 재개해도 소급 수집되지 않는다.
구현: 파일감시(watch.rs)는 일시정지 중에도 새로 쓰인 바이트를 읽고 cursor(offset/mtime)는 그대로
전진시키지만, 라인 파싱/스크럽/`db::ingest()` 호출은 전부 생략한다. HTTP 인제스트(`/v1/ingest`)는
저장 없이 `{ok:true, inserted:0, paused:true}`로 즉시 응답한다. 두 진입점 모두 같은 런타임 플래그
(`Arc<AtomicBool>`, `lib.rs` setup에서 생성해 공유)를 참조하므로 앱 재시작 없이 즉시 반영된다.

상태는 **재시작에도 유지**된다 — `~/.logroom/config.json`의 `capture.capturePaused`(기본 `false`)에
영구 저장되며, 앱 기동 시 이 값으로 런타임 플래그를 초기화한다. `set_capture_paused` 커맨드는 기존
설정을 로드해 `capturePaused` 필드만 바꿔 저장하는 부분 갱신이라 다른 캡처 설정(경로/정책 등)을
덮어쓰지 않는다.

Slack 등 폴링 커넥터(`src/capture/slack.rs`)도 동일한 런타임 플래그를 사이클 최상단에서 확인해, 일시정지 중에는 커서를 그대로 둔 채 Slack API 호출 자체를 내지 않는다(아웃바운드 네트워크 0 원칙 유지).

## 위협 모델 (로컬 제품 관점)

| 위협 | 대응 |
|------|------|
| 로컬 다른 프로세스가 인제스트 남용 | 토큰 + localhost 바인딩 |
| 디스크 접근 악성코드가 DB 탈취 | 파일 perm + (옵션)SQLCipher, 키체인 분리 |
| 네트워크 도청 | 기본 아웃바운드 0, 커넥터는 HTTPS |
| 시크릿이 프롬프트에 섞여 저장 | 스크럽 룰 + 사용자 제외 |
| 백업으로 평문 유출 | export 시 암호화 옵션 안내 |
| (판매) "진짜 로컬인가" 불신 | 네트워크 투명성 페이지 + 공증 + (여력시)3자 감사 |
